## Changes to Existing Entities

### `Athlete` (table: `athletes`) — Two New Columns

No new tables. Two nullable columns are added to the existing `athletes` table.

| Column                               | Type     | Nullable | Default | Purpose                                                                                                                                                                                               |
| ------------------------------------ | -------- | -------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pending_onboarding_data`            | JSON     | Yes      | NULL    | Stores the training profile JSON captured by the onboarding conversation (all fields _except_ Garmin credentials) after the athlete confirms their profile and while the bot awaits modal submission. |
| `pending_onboarding_data_created_at` | DateTime | Yes      | NULL    | UTC timestamp set when `pending_onboarding_data` is written. Used to enforce the 24-hour TTL.                                                                                                         |

#### State Machine

The two new columns encode a new intermediate onboarding state:

```
onboarding_complete = False
pending_onboarding_data = NULL
pending_onboarding_data_created_at = NULL
→ "In conversational onboarding" (existing behaviour)

onboarding_complete = False
pending_onboarding_data = {...profile JSON...}
pending_onboarding_data_created_at = <utc datetime>
→ "Awaiting Garmin credentials via modal" (NEW state)

onboarding_complete = True
pending_onboarding_data = NULL
pending_onboarding_data_created_at = NULL
→ "Onboarding complete" (existing behaviour, pending data cleared on success)
```

#### TTL Expiry Check

```python
from datetime import datetime, timedelta

PENDING_DATA_TTL_HOURS = 24

def is_pending_data_expired(athlete: Athlete) -> bool:
    if athlete.pending_onboarding_data_created_at is None:
        return False
    age = datetime.utcnow() - athlete.pending_onboarding_data_created_at
    return age > timedelta(hours=PENDING_DATA_TTL_HOURS)
```

#### Lifecycle

| Event                                                             | `pending_onboarding_data`          | `pending_onboarding_data_created_at` |
| ----------------------------------------------------------------- | ---------------------------------- | ------------------------------------ |
| `<onboarding_complete>` tag parsed in `handle()`                  | Set to profile JSON dict           | Set to `datetime.utcnow()`           |
| Modal submitted successfully → `_complete_onboarding()` completes | Set to `NULL`                      | Set to `NULL`                        |
| `!admin reset-onboarding <uid>`                                   | Set to `NULL`                      | Set to `NULL`                        |
| TTL expired — athlete clicks button or sends a message            | (checked, not cleared until reset) | (checked)                            |

#### `pending_onboarding_data` JSON Schema

```json
{
  "name": "string",
  "age": "integer or string integer",
  "race_type": "marathon | half_marathon | 10k | 5k",
  "race_date": "YYYY-MM-DD",
  "target_time_seconds": "integer",
  "weekly_mileage_km": "float",
  "training_days": "integer or string integer",
  "experience_level": "beginner | intermediate | advanced",
  "injuries": "string or 'none'",
  "city": "string"
}
```

Note: `garmin_email` and `garmin_password` are **not** included. They are extracted from the modal `view["state"]["values"]` at submission time and merged into a copy of this dict before passing to `_complete_onboarding()`.

## Impact on Existing Tests

All existing unit tests that call `_complete_onboarding()` directly pass a `data` dict and a mock `Athlete`. Since the `Athlete` mock does not set `pending_onboarding_data`, those tests are **unaffected**. The two new columns are `nullable=True` with no default — existing rows have `NULL` in both columns, which the new state machine interprets correctly as "not awaiting credentials."
