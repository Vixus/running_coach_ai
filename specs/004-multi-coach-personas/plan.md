# Implementation Plan: Multi-Coach Personas

**Branch**: `004-multi-coach-personas` | **Date**: 2026-04-05 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/004-multi-coach-personas/spec.md`

## Summary

Allow athletes to choose from multiple named coaching personas, each with a distinct voice and communication style. The selected persona is injected as a block at the top of `build_system_prompt()` (and as the system prompt for scheduler-driven calls), replacing the current single global `COACH_PERSONA` constant. Coach selection is woven into Claude's onboarding conversation (persisted via `<onboarding_complete>` JSON) and is switchable post-onboarding via a new `<coach_switch>key</coach_switch>` side-effect tag. Existing athletes receive the default coach silently via a DB migration.

## Technical Context

**Language/Version**: Python 3.11+  
**Primary Dependencies**: SQLAlchemy 2.x, Anthropic Claude API, Slack Bolt, APScheduler, Alembic  
**Storage**: SQLite via SQLAlchemy — one new column: `Athlete.coach_key TEXT`  
**Testing**: pytest — unit tests for persona registry, tag extraction, migration, onboarding JSON parsing  
**Target Platform**: Linux (Docker / Synology NAS)  
**Project Type**: Slack bot service  
**Performance Goals**: No additional latency — persona block is an in-process string lookup (O(1))  
**Constraints**: No new external API calls; no new DB tables; `coach_key` must be validated against in-process registry before persisting  
**Scale/Scope**: ~2–10 athletes; 3 coach personas at launch

## Constitution Check

_GATE: Must pass before Phase 0 research. Re-check after Phase 1 design._

- [x] **I. Athlete Data Isolation**: `coach_key` is read from the `athlete` object already in scope — no new cross-athlete queries introduced. All persona lookups are athlete-scoped.
- [x] **II. AI Coach Persona Integrity**: This feature directly enhances persona integrity by replacing the implicit single-coach assumption with a named, selectable persona system. XML tag processing pattern extended with `<coach_switch>`.
- [x] **III. Metric-First Architecture**: No changes to distance/pace storage or display logic. Coach personas operate exclusively on language/tone.
- [x] **IV. Encrypted Secrets Management**: No credential changes. Coach key is a plain string, not a secret.
- [x] **V. Graceful Degradation**: If `coach_key` is missing, None, or unrecognised, `get_persona()` falls back to the default coach. No crash path.
- [x] **VI. Structured Observability**: Coach switch events logged with athlete_id and new coach_key at INFO level.
- [x] **VII. Test-First Development**: Unit tests planned for persona registry, `get_persona()` fallback, `extract_coach_switch()`, onboarding JSON `coach_key` parsing, and migration default.
- [x] **VIII. Configuration as Code**: Coach personas defined in `coach/personas.py` (Python module) — no hardcoded values in callers; no env vars needed (personas are stable application code, not deployment config).

All constitution checks pass. No violations to justify.
